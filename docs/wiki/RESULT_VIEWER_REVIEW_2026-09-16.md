# 결과 이미지 자동 맞춤 — 2026-09-16

## 변경

- 이미지 크게보기의 Grid 자동 최소 크기 때문에 원본 이미지가 창의 세로 높이를 밀어내고, `overflow: hidden`으로 하단이 잘리는 문제를 수정했다.
- 행·열을 `minmax(0, 1fr)`로 제한하고 이미지의 최대 너비·높이를 해당 영역에 맞춘다. 원본 비율을 유지하며 이미지 전체를 중앙에 표시한다. 별도 확대율 조절이나 스크롤이 필요하지 않다.
- `100dvh`와 안전 영역 여백으로 모바일 브라우저 높이 변화와 닫기 버튼 공간을 반영한다. 이미지 보기 중 배경 페이지의 스크롤바를 숨기며, 닫으면 원래 스크롤 동작으로 복구한다. 대화상자는 예외적인 넘침을 숨기지 않도록 `overflow: auto`를 사용한다.
- 출력 렌더러는 기존의 2048×1024 PNG와 좌우 각각 960×720 장면을 유지한다. 모바일·태블릿 화면 너비나 DPR로 출력 해상도와 구성을 바꾸지 않는다. 화면용 축소는 저장 이미지에 적용되지 않는다.

## 브라우저 검수

실제 결과 렌더러와 `ResultImageDialog`를 불러오는 별도 개발용 화면에서 사물함 결과 PNG를 생성했다. 학생 활동 저장 데이터는 변경하지 않았다. 같은 대화상자를 연 상태에서 CSS 뷰포트를 전환했다.

| CSS 뷰포트 | 화면에 표시된 이미지 | 대화상자 넘침 |
|---|---|---|
| 1920×1080 | 1884×942 | 없음 |
| 1366×768 | 1330×665 | 없음 |
| 1024×768 | 988×494 | 없음 |
| 768×1024 | 732×366 | 없음 |
| 390×844 | 354×177 | 없음 |
| 844×390 | 600×300 | 없음 |
| 320×568 | 284×142 | 없음 |

- 모든 크기에서 원본 2048×1024, 표시 비율 2:1, 이미지 전체와 닫기 버튼의 화면 내부 배치를 확인했다. 대화상자의 `scrollWidth/Height`와 `clientWidth/Height`가 같았다.
- 데스크톱 창, 작은 모바일 및 모바일 가로 화면을 직접 보며 이미지 하단까지 표시되는 것을 확인했다. 열린 상태에서 휠을 움직여도 이미지가 잘리거나 배경이 움직이지 않았다.
- X 및 Escape로 닫기, 이미지 보기 버튼으로 초점 복귀를 확인했다. X로 닫은 뒤 휠 입력으로 배경의 `scrollY`가 0→720으로 바뀌며 스크롤이 복구되었다.
- 실제 iPad/iPhone/Android 터치·안전 영역·길게 눌러 저장, 패들렛 게시, 교실 프로젝터 검수는 이번 범위에서 수행하지 않았다.

## 자동 검사

- 기기 너비·높이·DPR 네 조합에서도 PNG가 2048×1024이고 두 장면이 각각 960×720인 회귀 검사를 추가했다.
- 전체 테스트 16파일·86개 통과. 타입 검사 및 빌드 통과. 에셋 검사 127/127, 누락·형식 오류·미사용 파일 없음.
- 첫 검사에서 동시 작업 중인 퀴즈 액션과 기존 테스트의 불일치가 발견되었으나, 해당 작업 갱신 후 재검사에서 통과했다. 이미지 수정에서 퀴즈 로직을 변경하지 않았다.
- 커밋·푸시·배포는 수행하지 않았다.
